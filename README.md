# Учёт байера

Локальное desktop-приложение для учета закупок, продаж, расходов, склада и финансового результата байера.

Приложение работает на Windows, использует Electron и React, хранит данные локально на устройстве и не требует интернет-соединения или внешней базы данных.

## Возможности

### Обзор

- Выручка за неделю, месяц или квартал.
- Чистая прибыль, себестоимость, расходы и налоговый резерв.
- Дебиторская задолженность клиентов.
- Быстрые действия для создания закупки, продажи и расхода.
- Календарь заработка с переключением месяцев.
- Сумма заработка по каждой дате.
- Общая сумма за месяц.
- Количество продаж и дней с доходом.
- Средний заработок за активный день.
- Лучший день месяца.
- Последние продажи.

Календарь использует все сохраненные продажи, поэтому переход на предыдущий или следующий месяц показывает фактические данные, а не только текущий выбранный период.

### Закупки

Для каждой закупки можно указать:

- дату;
- страну;
- площадку;
- название товара;
- категорию;
- ссылку;
- цену товара и его валюту;
- курс валюты товара к основной валюте;
- внутреннюю доставку в KZT;
- международную доставку в валюте товара;
- пошлину или НДС;
- комиссию агента;
- статус закупки.

Итоговая себестоимость пересчитывается автоматически:

```text
цена товара * курс товара
+ внутренняя доставка в тенге
+ международная доставка в валюте товара * курс товара
+ пошлина / НДС
+ комиссия агента
```

Доступные статусы закупки: `Заказано`, `В пути`, `На складе`, `Продано`.

### Продажи

- Создание продажи с датой, товаром, клиентом и ценой.
- Учет фактически полученной суммы.
- Статусы оплаты: полная предоплата, частичная оплата, постоплата, долг.
- Автоматический расчет маржи.
- Редактирование продажи.
- Удаление продажи с возвратом товара в статус `На складе`.
- Смена товара при редактировании продажи синхронизирует статусы старого и нового товара.

### Расходы

Операционные расходы группируются по категориям:

- реклама;
- упаковка;
- курьерка;
- комиссия платежной системы;
- прочее.

Для расхода доступны дата, сумма и комментарий.

### Склад

На складе отображаются закупки со статусом `На складе` и общая сумма денег, замороженная в товарах.

### Дебиторка и возвраты

- Список клиентов, которые должны деньги.
- Сумма задолженности по каждой продаже.
- Ручной учет возвратов от поставщиков.
- Статус, причина, дата и сумма возврата.

### Налоги

- Налоговый резерв рассчитывается как процент от выручки.
- Ставка настраивается пользователем.
- Отдельно отображаются рекомендуемый резерв, уже уплаченная сумма и остаток.
- Есть история налоговых платежей.

### Отчеты

- Выручка, себестоимость, расходы и чистая прибыль за выбранный период.
- Маржинальность.
- Прибыль по странам закупки.
- Экспорт отчета в Excel/CSV.
- Экспорт отчета в PDF.

### Настройки

- Основная валюта: RUB, KZT, USD или EUR.
- Сохраненные курсы KZT и USD к основной валюте.
- Ставка налога.
- Запуск приложения вместе с Windows.
- Отображение раздела склада.
- Светлая или темная тема.
- Сохранение резервной копии.
- Восстановление резервной копии с немедленным обновлением интерфейса.
- Адаптивный интерфейс для узких экранов ноутбука и телефона.
- Автономный web/PWA-режим с хранением данных в браузере без интернета.

## Технологии

- React.
- Vite.
- Electron.
- XLSX для Excel/CSV-экспорта.
- Electron IPC для безопасной связи интерфейса и локального хранилища.
- JSON-файл в каталоге пользовательских данных Electron.

## Локальные данные

Данные хранятся локально в JSON-файле Electron:

```text
buyer-finance.json
```

При сохранении существующего файла создается резервный файл:

```text
buyer-finance.json.bak
```

Основные разделы данных:

- `settings` — настройки приложения и курсы валют;
- `purchases` — закупки;
- `sales` — продажи;
- `expenses` — операционные расходы;
- `taxPayments` — налоговые платежи;
- `refunds` — возвраты.

Внешние базы данных и сетевые API не используются.

## Установка

Требуется Node.js с npm.

```bash
npm install
```

## Запуск в режиме разработки

```bash
npm run dev
```

Команда запускает Vite и Electron одновременно. Адрес Vite:

```text
http://127.0.0.1:5173/
```

## Сборка интерфейса

```bash
npm run build
```

Собранные web-файлы помещаются в каталог `dist`.

Если в `dist` уже находится запущенный или заблокированный Windows-файл Electron, можно обновить web-сборку без очистки каталога:

```bash
npx vite build --emptyOutDir false
```

## Запуск собранного приложения

```bash
npm start
```

## Сборка установщика

```bash
npm run dist
```

Команда собирает production web-файлы и создает Windows-установщик и portable-версию через electron-builder.

Для portable-сборки Windows:

```bash
npm run dist:portable
```

После `npm run dist` в каталоге `dist` создаются установщик Windows и portable-версия. Файл `Учёт байера.exe` в `dist/win-unpacked` — распакованная production-версия для локальной проверки.

На телефоне `.exe` не запускается. Для телефона используется web/PWA-режим: после открытия собранного интерфейса его можно установить на главный экран браузера. В этом режиме данные хранятся локально в браузере, а функции автозапуска Windows и экспорта PDF доступны только в Electron-приложении.

## Важные правила учета

1. Все суммы продаж, расходов, налогов и итоговые себестоимости отображаются в основной валюте приложения.
2. Цена товара может быть в отдельной валюте и пересчитывается через курс товара.
4. Внутренняя доставка всегда вводится в тенге; отдельный курс KZT не нужен.
5. Международная доставка вводится в валюте товара.
6. Международная доставка использует тот же курс, что и цена товара.
6. Международная доставка вводится в валюте товара и использует тот же курс, что и цена товара.
7. Если основная валюта — KZT, курс KZT к KZT автоматически равен 1 и отдельно не вводится.
8. Изменение основной валюты не конвертирует старые числовые записи автоматически, поэтому при смене валюты нужно проверять сохраненные данные.
9. Удаление продажи возвращает связанную закупку на склад.
10. Backup рекомендуется делать перед массовым изменением данных или сменой основной валюты.

## Проверка проекта

Быстрая проверка исходников:

```bash
npm run build
```

Проверка без очистки существующего `dist`:

```bash
npx vite build --emptyOutDir false
```

## Ограничения

- Курсы валют вводятся вручную и не обновляются автоматически.
- Приложение рассчитано на одного локального пользователя.
- Нет синхронизации между несколькими компьютерами.
- История изменений записей не ведется.
- Старые записи, созданные до добавления отдельных курсов доставки, могут потребовать проверки при редактировании.
